# Delivery plan

Companion to `PRD.md`. Every step is a branch and a pull request. Nothing is committed before the gates have run locally and the author has read the diff and approved it; the author then reviews the pull request again on GitHub and merges it by hand, only when every required check is green and the review notes in the description are addressed. The AI tooling never commits, pushes or opens a pull request without that approval, and never merges. Review and audit findings are proposals: nothing is fixed until the author has read, understood and approved the finding, and open questions from the AI tooling are answered by the author, never assumed. Commits are small and conventional (`feat:`, `fix:`, `docs:`, `test:`, `chore:`), so the history reads as the sequence below.

## Time budget

Friday: research, PRD, questions to Wolfpack, repository initialised (PR 1). Saturday: PRs 2–6. Sunday: PRs 7–10. Monday morning: PRs 11–12, tag `v1.0.0`, send the email before 10:00.

Out of scope for this deliverable rather than deprioritised, and named as future work in the audit, self-review and README reports beside the Capacitor/Expo path: Playwright end-to-end, the PWA manifest and service worker, and a pass with a screen reader. If time runs short, the order of sacrifice is: React Compiler, second self-review round, then the soak test is shortened (never dropped). Never sacrificed: the one-command run with the wizard, the 100% coverage gate, the audit and self-review reports, the README. Every PR ships with its tests; coverage never drops below the threshold on `main`.
